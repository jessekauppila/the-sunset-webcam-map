# solo2 — The Beat (phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every frame change on both solo2 screens lands on one wall-clock tick; a frame is one beat, a still is a whole number of beats, a camera change is one beat; the rate never changes.

**Architecture:** The plan in `app/lib/solo2/plan.ts` becomes integer beats but keeps its seconds-shaped rendering fields, so the glass, the preview and the tape keep reading the same shape. Three solo2 dials (`beat`, `dwellBeats`, `changeBeats`) replace `dwellS`, `minStepS`, `fadeS` and `offsetS` in the solo2 namespace; `dialsFrom2` derives the old seconds fields from them so every older consumer still works. The advance endpoint snaps a dwell's start to the nearest tick and stores it, so the glass's clock starts on the grid. The dip's burn-down moves into the arriving dwell's change beat.

**Tech Stack:** Next.js 15 app router, TypeScript, Vitest + Testing Library, Neon Postgres via `@neondatabase/serverless`. Tests run with `npx vitest run <path>`.

**Spec:** `docs/superpowers/specs/2026-09-14-solo2-beat-and-rendezvous-design.md` §2 (the beat), §4.2 (the dwell line), §5 (replay). §3 (the rendezvous) and §4.1 (one tape for two screens) are phase 2 and NOT in this plan.

## Global Constraints

- `beatS` is a divisor of 60: one of 2, 3, 4, 5, 6, 10, 12, 15, 20, 30 (spec §2.1). Default 4.
- Ticks are `60·m + k·beatS` seconds on the wall clock, i.e. `ms % (beatS·1000) === 0` since the epoch is on a minute boundary.
- A dwell of `n` frames occupies `changeBeats + n + restBeats` beats, `restBeats = max(0, dwellBeats − n)` (spec §2.2, §2.3). `changeBeats` is 0 when `transition` is `cut`.
- The dwell ends on a tick and the next begins on that tick (spec §2.2). The advance snaps to the **nearest** tick (an amendment to spec §2.6 "at or after": the kiosk fires at the tick and the request lands a few hundred ms later; "after" would lose a beat on every change).
- `exitS` is always 0 on the beat: the whole camera change is the arriving dwell's change beat, burn-down first half, rise second half (spec §2.2).
- No migration in this phase. `kiosk_screen_state.shown_since` and `kiosk_draws.shown_at` simply receive the tick instead of `now()`.
- `solo` (the version without a camera run) is untouched: its dials, engine and grid stay as they are.
- Work in a sibling worktree: `scripts/wt.sh new feat/solo2-beat` from the main checkout. Stage explicit paths. Verify the branch in the same command as every commit.
- Commit messages end with the attribution lines the session reminder gives.

```ts
import type { Solo2Dials } from './types';

/**
 * The beat (beat spec §2). Every frame change on both screens lands on one
 * tick of the wall clock; a frame is one beat; a dwell is whole beats.
 */

/** The beats a dial may choose: divisors of 60, so ticks fall on seconds 0, b, 2b … of every minute. */
export const BEAT_OPTIONS = [2, 3, 4, 5, 6, 10, 12, 15, 20, 30] as const;

/** The tick closest to `ms`. The advance uses this: the kiosk fires at a tick and the request lands a little after it. */
export function nearestTick(ms: number, beatS: number): number {
  const b = Math.max(1, beatS) * 1000;
  return Math.round(ms / b) * b;
}

/** The first tick at or after `ms`. */
export function nextTick(ms: number, beatS: number): number {
  const b = Math.max(1, beatS) * 1000;
  return Math.ceil(ms / b) * b;
}

/**
 * One dwell's timeline. The seconds fields are what the glass, the preview
 * and the tape render from and keep their meaning; the beat fields say how
 * they were made. `exitS` is always 0 on the beat: the whole camera change
 * is the arriving dwell's change beat (spec §2.2).
 */
export interface DwellPlan {
  /** The whole dwell, seconds: `totalBeats × beatS`. */
  dwellS: number;
  /** Frames the dwell plays, at least 1. */
  frames: number;
  /** One beat. */
  stepS: number;
  /** The last frame's step: one beat plus the rest. */
  lastStepS: number;
  leadS: number;
  /** The change beat at the front, seconds; frame 1's own beat begins when it ends. */
  arrivalS: number;
  /** Always 0 (kept so older renderers read the same shape). */
  exitS: number;
  beatS: number;
  /** Beats of veil at the front; 0 for a cut. */
  changeBeats: number;
  /** Extra beats on the last frame, so a short run still holds the dwell floor (spec §2.3). */
  restBeats: number;
  /** `changeBeats + frames + restBeats`. */
  totalBeats: number;
}

/** What `fitPlan` reads. `transition` decides whether the change beat exists; `sameCameraFadeS` is for `stepFadeS`. */
export type PlanDials = Pick<Solo2Dials, 'beatS' | 'dwellBeats' | 'changeBeats' | 'leadS'>
  & Partial<Pick<Solo2Dials, 'transition' | 'sameCameraFadeS'>>;

/** Beats of change at the front of a dwell: none for a cut, else the dial. */
export function changeBeatsOf(d: Pick<PlanDials, 'changeBeats' | 'transition'>): number {
  if (d.transition === 'cut') return 0;
  return Math.max(0, Math.floor(d.changeBeats));
}

/**
 * The beat rule (spec §2.2, §2.3):
 *
 *     rest  = max(0, dwellBeats − n)
 *     total = change + n + rest
 *
 * The rate never changes. A run shorter than the dwell floor rests on its
 * last frame, the picture it arrived at; a longer run simply takes more beats.
 */
export function fitPlan(d: PlanDials, frames: number): DwellPlan {
  const n = Math.max(1, Math.floor(frames));
  const beatS = Math.max(0.001, d.beatS);
  const changeBeats = changeBeatsOf(d);
  const restBeats = Math.max(0, Math.floor(d.dwellBeats) - n);
  const totalBeats = changeBeats + n + restBeats;
  const dwellS = totalBeats * beatS;
  return {
    dwellS, frames: n, stepS: beatS, lastStepS: beatS * (1 + restBeats),
    leadS: Math.min(dwellS, Math.max(0, d.leadS)),
    arrivalS: changeBeats * beatS, exitS: 0,
    beatS, changeBeats, restBeats, totalBeats,
  };
}
```

```ts
/**
 * The line the studio prints: `8 frames × 4 s · 1 beat change`, `1 frame ×
 * 4 s · 1 beat change · rests 2 beats`, `· lead 4 s` when the lead is on.
 */
export function describePlan(p: DwellPlan): string {
  const s = (n: number) => `${Number(n.toFixed(1))} s`;
  const beats = (n: number) => `${n} beat${n === 1 ? '' : 's'}`;
  const frames = `${p.frames} frame${p.frames === 1 ? '' : 's'} × ${s(p.stepS)}`;
  const change = p.changeBeats > 0 ? ` · ${beats(p.changeBeats)} change` : '';
  const rest = p.restBeats > 0 ? ` · rests ${beats(p.restBeats)}` : '';
  const lead = p.leadS > 0 ? ` · lead ${s(p.leadS)}` : '';
  return `${frames}${change}${rest}${lead}`;
}
```

```ts
/** The still and its spread, as dial fields; the spread is optional so older callers read as the dial. */
export interface BudgetDials { dwellBeats: number; dwellBoost?: number; dwellTrim?: number }

/**
 * The still for a draw of `e`, in whole beats (beat spec §2.2): a non-sunset,
 * and the weakest sunset present, hold the dial less the trim; the strongest
 * sunset present holds the dial plus the boost; sunsets between sit by rank.
 * Rounded to whole beats, never below one. Read off the camera, not off the
 * drawn frame (`standsFor`).
 */
export function budgetBeats<T extends RunEntry>(
  e: Pick<BinEntry, 'bin'> & Partial<T>, d: CapDials & BudgetDials, entries?: T[], cameraRun = true,
): number {
  const boost = (d.dwellBoost ?? 0) / 100;
  const trim = (d.dwellTrim ?? 0) / 100;
  if (boost === 0 && trim === 0) return Math.max(1, Math.round(d.dwellBeats));
  const stands = standsFor(e, entries, cameraRun);
  const rank = stands.bin === 'sunset' ? standing(stands, d, entries, cameraRun) : 0;
  return Math.max(1, Math.round(d.dwellBeats * (1 - trim + (trim + boost) * rank)));
}

/** `d` with its still replaced by the draw's budget, ready for fitPlan. */
export function planDialsFor<T extends RunEntry, D extends CapDials & BudgetDials>(
  e: Pick<BinEntry, 'bin'> & Partial<T>, d: D, entries?: T[], cameraRun = true,
): D {
  return { ...d, dwellBeats: budgetBeats(e, d, entries, cameraRun) };
}
```
